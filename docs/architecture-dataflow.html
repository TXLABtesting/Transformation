1. System overview

The portal is a Next.js 14 application (App Router, TypeScript, RTL Arabic UI) backed by PostgreSQL 16 through Prisma ORM. Users sign in with UAE PASS (OIDC); sessions are stateless HMAC-signed httpOnly cookies (no sessions table). An optional internal, OpenAI-compatible model powers the AI review step. One codebase serves all the roles — مشرف النظام (admin), منسق المسار في الجهة, رئيس المسار ونائبه, and اللجنة الوطنية (الرئيس والأمانة العامة); every screen derives from a single role-scoped view-model, so what a user can see is decided in one place. The admin gets a dedicated console for managing users & roles and assigning the stream heads and national committee.

6. Data flow — bulk import (workplan file)

The coordinator downloads the per-stream Excel template from the bulk-upload step («تنزيل نموذج المسار») — its columns are generated from the same field definitions as the entry form (STREAM_FIELDS), including dropdowns for every select field. In the services stream the الخدمة / الخدمة الفرعية columns are dropdowns from the entity's own service_catalog rows.

StepWhat happens
1 · Upload .xlsxThe importer finds the header row by matching the exact column labels first (fuzzy match only as a fallback), one column per field.
2 · Normalize & deriveRows are normalized like the form: conditional fields are cleared when inapplicable (نوع عملية الدعم، نظام/نسبة الأتمتة), automation is clamped (كلياً = 100٪، جزئياً ≤ 95٪), and أولوية التحول is derived from the stream matrix.
3 · Review screenEvery row shows its verdict; rows with missing required fields are flagged «بيانات ناقصة». A confirm button commits the import.
4 · CommitComplete rows are submitted (قيد الاعتماد — رئيس المسار is notified); incomplete rows are saved as drafts. Selecting drafts later offers «إكمال وإرسال» / «إرسال للاعتماد» with a popup listing the missing fields.

Nothing is invented: whatever the file does not carry stays blank for manual completion.

8. Access provisioning & the admin console

Accounts live in users (FK users.role → roles.key). One actor provisions everyone: the system admin creates and manages all accounts for all entities — stream heads and deputies (with their stream), coordinators (with entity + stream), and the national committee. There is no self-service team-setup screen.
